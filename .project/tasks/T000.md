# T000 — Workflow preparation

- Milestone: Setup
- Dependencies: None
- Model suitability (advisory, not assignment): Any repository-capable model.
- Status: see [TASKS.md](../TASKS.md); only the coordinator assigns this task.

## Scope

Create the sequential tracking system and commit the existing design baseline. No game source, dependencies, branches, worktrees or publication.

## Required inputs

Read [AGENTS.md](../../AGENTS.md), [STATUS.md](../STATUS.md), [HANDOFF.md](../HANDOFF.md) and any existing task report first. Then read: All five root design documents; the owner's sequential-workflow request; initial Git status/log.

Sources: [requirements](../../REQUIREMENTS.md), [architecture](../../ARCHITECTURE.md), [milestones](../../IMPLEMENTATION_PLAN.md), [test plan](../../TEST_PLAN.md). Two-digit T01–T23 identify test groups; three-digit T000–T023 identify work tasks.

## Expected files or modules

.project/STATUS.md, TASKS.md, HANDOFF.md, DECISIONS.md, tasks/T000.md–T023.md, reports/README.md, reports/T000.md; AGENTS.md; execution guidance/mapping in IMPLEMENTATION_PLAN.md. Include unchanged REQUIREMENTS.md, ARCHITECTURE.md and TEST_PLAN.md in the baseline commit.

Every task also updates its report, TASKS, STATUS and HANDOFF as needed; file lists are intended scope, not permission for unrelated edits.

## Acceptance criteria

All requested tracking roles exist; each implementation task has scope/inputs/files/acceptance/tests and dependencies; all P1–P10/P7a criteria map to tasks. Sequential approval/commit/stop rules are explicit. Existing rule/architecture/test documents remain unchanged. Only task-owned documentation is committed on the existing branch; unrelated filelist.txt remains untouched. Delivery is REVIEW, not self-approved DONE.

Acceptance reference: All milestones (mapping only); no product implementation.

## Required tests

Document structure/local-link checks; unique IDs, valid statuses, acyclic dependencies, complete milestone and test-group mapping; original-file hashes; git diff --cached --check; staged scope review; post-commit git status/log/show. No application tests are applicable.

Run only commands supported by this task's resulting repository. Report exact commands/results and any unrun checks; do not weaken acceptance because a tool/device is unavailable.

## Delivery and stop

Follow [report requirements](../reports/README.md). Commit only task-owned changes with prefix `T000:`, set REVIEW only when required work/checks are ready, and stop. Only explicit coordinator acceptance makes DONE. For interruption/blockers, checkpoint progress with precise resume instructions. Do not start a successor.
