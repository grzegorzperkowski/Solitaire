# T025 — Eliminate delayed court artwork rendering

- Milestone: P8 follow-up
- Dependencies: T017 DONE
- Assigned: 2026-10-11 by the human coordinator (“the card appears, but its icon loads with a delay; can this be fixed?”)
- Implementer: Codex
- Status: see [TASKS.md](../TASKS.md)

## Scope

Keep the twelve J/Q/K court illustrations crisp and vector while reducing their transfer and parse cost enough that they render promptly with their card. Keep aggregate gzip size of all court assets below 400 KiB and each file below 60 KiB. Do not change card appearance or add runtime dependencies.

## Optimization options

| Option | Fit for this issue | Decision |
| --- | --- | --- |
| SVGO: remove redundant XML and reduce path precision | Directly reduces transfer and SVG parsing while retaining vector art. | Use, then compare at card size/DPR 1–3. |
| HTTP Brotli/gzip | Reduces transfer only; verify actual hosted response headers and timing. | Record as deployment verification; do not assume host behavior. |
| Hashed-asset browser cache | Helps repeat visits, not first load. Vite already emits content-hashed asset names. | No app change. |
| Replace with `<img>` | These portraits are already separate external SVGs referenced by SVG `<image>`; changing element alone does not remove cold fetch or SVG decode. | Defer unless measurements show priority or decode differences. |
| Simplify paths, filters and repeated shapes | Useful if Performance profiling shows paint/raster work remains after size reduction. | SVGO handles safe path/XML reductions; further hand simplification needs evidence. |
| Lazy loading | Would delay a visible card portrait; hidden cards do not render their faces. | Do not lazy-load visible card art. |
| Preload | Could help only if the resource waterfall shows late discovery/low priority; preloading all twelve risks exceeding the first-load budget. | Defer until waterfall evidence. |
| WebP/AVIF | May lower decode/paint cost, but trades away vector scaling and can soften detail. | Defer unless vector optimization still leaves measured rendering delay. |

The coordinator supplied a broader optimization analysis; these options are scoped here to the measured cause rather than adopted wholesale.
