## Implementation
Added Menu action “Ponów dostęp do zapisu” and retries on window focus/document foreground. The existing acquisition path probes the same mode-specific lock with ifAvailable. A successful retry reloads the latest save while keeping the old session read-only, so newer moves/preferences cannot be overwritten by stale state. Occupied locks keep the reader frozen. A rejected retry shows feedback and stays read-only rather than enabling the initial-start fallback. Pending probes coalesce, successful reload keeps further requests suppressed, and destroyed controllers ignore late callbacks. Without Web Locks, or when a conflicting controller already holds its lock, retry reloads through the existing validation/conflict mechanism. Focus listeners are removed on destroy. No changes to save schema, mode separation or engine.
