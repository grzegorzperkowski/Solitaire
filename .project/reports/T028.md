## Scope and approach

- Bounded Best-First Search planner (`searchSmartHint(state, knownCards, options)`) using binary heap priority queue.
- Lexicographic ordering: primary utility score $U$ descending, path length $L$ ascending, foundation-to-tableau penalty $B$ ascending, FIFO tie-breaking.
- Utility scoring parameters: $U = 120H + 65W + 40F + 20I + 10M - 4L - 50B$.
- Strict information boundaries: branches stop on revealing a tableau card, drawing unknown stock cards, or exposing an unknown card under waste fan in Draw 3. Newly revealed cards at the boundary are masked so hidden values never leak into mobility calculations ($M$ and $B$).
- Deduplication via `progressStateKey(state, knownCards)`.
- Generator interface yielding periodically to support cancelable, time-sliced app execution (~4 ms batching, max 100 ms total search budget).
- App integration in `src/app.js`: asynchronous scheduling via `requestSmartHint()` with immediate cancellation on state changes (moves, Undo, Redo, New Game, Restart, pause, dialogs, pagehide).
- UI presentation in `src/ui/input.js`, `render.js`, and `smart-hints.js`: non-modal explanation in `#hint-notice`, screen-reader Polish announcements via `#live-announcer`, card destination highlighting, without altering card DOM nodes or interrupting gestures.
- Fully compatible with 320 px CSS viewports without horizontal scroll.
- Zero runtime dependencies; pure vanilla ES modules.
