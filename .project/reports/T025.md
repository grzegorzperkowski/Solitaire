## Work completed

- Root cause found: `src/ui/cards.js` renders each court portrait as an external nested SVG `<image>`. The card shell draws before this separately fetched and parsed image. Court files range from 251,327 to 764,175 bytes raw; the prior production build reported about 2.1 MiB gzip for all twelve.
- SVGO 4.1.0 with multipass and path precision 0 reduced all twelve assets to 330,570 bytes gzip; King of Clubs changed from 305,642 to 56,173 bytes gzip. A 156×235, DPR 3 visual comparison and a 320px DPR 3 gallery showed no material detail change. The final gallery screenshot was generated at `test-results/t017-cards-320-dpr-3.png` and inspected.
- Coordinator-supplied optimization options were assessed in [tasks/T025.md](../tasks/T025.md): SVGO is the direct cold-load fix; Brotli/gzip and cache need actual host verification; lazy-load is wrong for visible faces; preload, `<img>`, hand path simplification and WebP/AVIF remain measurement-driven follow-ups.
- Added a gzip budget regression test: all 12 files together are 330,570 bytes; the largest is 56,173 bytes. The test limits are 400 KiB total and 60 KiB per asset.
